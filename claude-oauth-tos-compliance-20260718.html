1 · The auth-model distinction

Anthropic runs two mutually exclusive contracts; each says so in its own text.

2 · The central clause — this is the whole question

Consumer Terms §3, prohibited uses, verbatim (Critic-verified 2026-07-18):

"Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, [you may not] access the Services through automated or non-human means, whether through a bot, script, or otherwise."

Read literally: automation on a subscription is restricted unless (a) you use an API key, or (b) Anthropic "otherwise explicitly permits it." Anthropic's own Claude Code documentation is that explicit permission — claude setup-token produces a one-year OAuth token that "authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan," expressly "for CI pipelines, scripts, or other environments where interactive browser login isn't available." Headless -p, the Agent SDK, subagents and unattended background sessions are all first-party documented surfaces.

Conclusion (HIGH): A single person running personal, unattended Claude Code automation on their own subscription OAuth token is a documented, supported pattern — not a ToS workaround. The automation ban targets un-permitted bot/script access; Anthropic explicitly permits its own tooling.

3 · Where the grey and the red actually are

  1. The --bare / Agent-SDK push toward API keys. --bare (Anthropic's recommended mode for scripted/SDK calls, and future default for -p) cannot use OAuth — it requires ANTHROPIC_API_KEY. GitHub Actions and GitLab CI docs document only API-key (or Bedrock/Vertex OIDC) credentials, never setup-token. Subscription OAuth automation is permitted, but Anthropic soft-steers serious/production automation toward API keys. Direction, not prohibition. (T1)
  2. The reselling line. Agent SDK docs: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products…" The primary text is worded around third-party developers exposing subscription auth to other end-users (reselling). It does not explicitly address one individual's own personal automation — genuinely unresolved either way. (T1)
  3. The economic-steering flux (live, moving). Across Apr–Jun 2026 Anthropic repeatedly changed how third-party/claude -p/SDK usage bills against a subscription — cut it, offered metered credits, reversed, paused. As of 2026-07-18 the Critic live-fetched support article 15036540: "Update June 15: We're pausing the changes… nothing has changed: Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription's usage limits." The separate metered credit pool is inactive — but this is an actively-changing area.

4 · Rate limits & concurrency — the practical ceiling

  • Weekly limits (Pro + Max) introduced 2025-07-28, effective ~2025-08-28, alongside the 5-hour rolling window; Anthropic estimated <5% of subscribers affected.
  • Hitting a limit throttles, it does not ban. Error docs: session/weekly/Opus limits "block further requests until the reset time shown." /model escapes only the Opus-specific limit. (T1 — H4 confirmed)
  • Concurrency draws from one shared pool. Multiple sessions/subagents "multiply token usage"; experimental agent teams ~7×. RPM/TPM concurrency ceilings are an API-org concept and do not apply to subscriptions. (T1)
  • Named enforcement trigger, per Anthropic's spokesperson at the Aug-2025 rollout: "24/7 background operation" + "sharing accounts and reselling access" — abnormal sustained volume and credential sharing, not automation per se.

5 · Token security — the sharpest operational weakness

  • macOS Keychain item Claude Code-credentials (accessToken/refreshToken/expiresAt). setup-token "does not save the token anywhere; copy it and set as CLAUDE_CODE_OAUTH_TOKEN." Devcontainer guidance: store as a secret/env var; "avoid mounting host secrets… prefer repository-scoped or short-lived tokens." (T1)
  • Revocation is unreliable. GitHub #43801: "Log out all sessions" / "Revoke all Claude Code instances" did not invalidate a live token ("security theater"). A collaborator claimed a server-side fix and closed it 2026-05-19, but users report recurrence through 2026-07-09, unanswered. Anthropic's "Managing active sessions" article covers only browser sessions — silent on CLI/OAuth tokens. Treat the OAuth token as effectively non-revocable in practice.
  • API keys are the opposite: configurable TTL (3h→30d/custom/Never), Console delete, GitHub secret-scanning auto-deactivation, WIF for short-lived CI. Genuinely revocable/rotatable/scopable. (T1)

6 · Account-risk factors — what actually gets people flagged

  • Abnormal sustained volume — 24/7 unattended runs, hundreds of fanned-out agents burning a weekly quota in hours. (Anthropic-named + community)
  • Credential/account sharing with other people; reselling. (T1 ToS + consensus)
  • Multiple accounts to dodge rate limits — mere account count is not the trigger; quota-dodging intent is. (consensus)
  • Token-pooling relay architectures across many accounts behind one endpoint. (speculative)
  • Opaque "Safeguards Team" suspensions — real, frustrating, causally unattributable.
  • Negative finding: No public ban report isolates one person, one legitimate token, official client, on their own Mac + own VPS as the trigger. A genuine "no evidence found" — weak reassurance, not a safe-harbor.

✦ Single clearest compliance risk in the current NexusOS setup

Not a ToS violation — an operational / blast-radius risk that sits on top of two grey areas. NexusOS runs (a) long-lived 24/7 agents — the pattern Anthropic itself named ("24/7 background operation") when it introduced enforcement — while (b) sharing one effectively-non-revocable OAuth subscription token across both the Mac and the VPS. If the VPS is compromised, there is no confirmed working way to revoke that token without re-minting on every host, and the sustained-volume profile is the closest thing to a documented flag trigger.

Highest-leverage mitigations, in order:
  1. Mint a separate claude setup-token per host (distinct Mac and VPS tokens); never copy the Mac's live Keychain credential to the VPS. Store the VPS token in a secrets manager / 0600 env file, never in git.
  2. For the VPS's unattended/headless lanes, prefer an ANTHROPIC_API_KEY (revocable, TTL-scoped, secret-scanned) over the OAuth token — removes the --bare incompatibility and insulates you from the subscription-billing flux.
  3. Instrument weekly-limit proximity and avoid pathological fan-out (hundreds of concurrent subagents) that mimics abuse.
  4. Keep it single-owner. The bright-line RED rules are exactly what NexusOS already avoids — keep it that way.

Anti-hallucination note: the concurrent one-token-two-machines question and the personal-vs-reseller line in the Agent SDK clause are genuinely unstated in Anthropic's primary sources. They are YELLOW because they are undocumented, not because a rule was found prohibiting them.
